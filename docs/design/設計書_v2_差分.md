**論点 2 5 枚目の置き方**: (a) 左寄せ・同じ幅 ／ (b) 2 列分の横長 ／ (c) 中央寄せ。**採用 (a)**。カードのテンプレートが 1 種で済み、空いた 6 セル目に定型文（D-12）と個人情報注記を入れて紙を使い切れる。(b) は横長用の 2 段目レイアウトが要り、(c) は右の余白が死ぬ。規則: 「定型文ブロックはグリッドでカードの次のセルに置く。カードが偶数枚（0・2・4）のときは 2 列分（grid-column: 1 / -1）に広げる」。res.message（体験 0 件）は定型文ブロックの先頭に太字で置く。

**論点 3 本命の表し方**: (a) 枠線の太さ＋朱の帯「◎ 本命」 ／ (b) 地色の塗り分け。**採用 (a)**。枠 3px #B7282E＋カード右上に朱塗り白字の帯「◎ 本命」（R3 §3 の旗形ラベルに倣う。clip-path の三角は付けない）。他のカードは 1px #054527。モノクロでは「3px vs 1px」と「◎ 本命」の文字で区別できる（D-24）。(b) は緑と朱の輝度差が約 20 で、モノクロで区別できない（R3 §1）。

**論点 4 体験／見学の表し方**: 【体験】＝深緑 #054527 塗り・白字の角タグ、【見学】＝白地・1px #054527 枠・深緑字の角タグ（R3 §4 の 1px 黒角タグ）。塗り反転なので grayscale でも判別でき、文字でも読める。

**論点 5 ラベル囲み（開催・予約・所要・費用・年齢）**: サイトの dl.info（dt 緑塗り白字・角丸 8px ＋ dd 白地。R3 §4）を小型化: ラベルは #41910F 塗り・白字・太字・8pt・角丸 4px・幅 4 文字分固定、値はその右に 9pt #222。2 列（開催／予約、所要／費用）＋年齢は 1 列分。値の表記は v1 A-5 表＋変更票 #1（「必須」→「要予約」）のまま。所要・費用が空のときはその組を出さず、行を詰める。

**論点 6 配色（D-24・R3 §1）**: 使ってよい色は §6 AC-18' の HEX 一覧 10 色だけ。曜日色（#A6961A・#00629F）と藍 #0F2350 は使わない（モノクロで区別できず、開催日は「22・24日」の文字で足りる）。地色 #F4F2EE は紙全体には敷かない（インクとモノクロ時の濃度のため。見立て箱の地だけ #F0E9DA）。塗りを印刷させるため `#sheet { -webkit-print-color-adjust: exact; print-color-adjust: exact; }` を必ず入れる（Chrome の既定は背景を印刷しない）。

**論点 7 書体（D-27）**: index.html の `<head>` で Google Fonts を読む。URL は R3 §2 のもの（`family=BIZ+UDPGothic:wght@400;700&family=Noto+Serif+JP:wght@400;700;900&display=swap`）。描画を止めないため `<link rel="stylesheet" media="print" onload="this.media='all'">` の非ブロック読込（media が print の間は描画を待たない。読めたら all に切替）。失敗時は font-family のフォールバック列で続行: 見出し `"Noto Serif JP","Yu Mincho","Hiragino Mincho ProN","MS Mincho",serif`、本文 `"BIZ UDPGothic","BIZ UDGothic","Yu Gothic UI","Meiryo",sans-serif`。印刷直前に `document.fonts.ready` を**最大 1.5 秒**だけ待ってから `#sheet` を組み立てる（計測 fit() がフォント差で狂わないため。待ちきれなければそのまま進む＝体験を止めない）。A-4 の「Web フォントを読まない」は推挙状と画面の見出しに限り緩める（D-27）。画面の見出しへの適用は game.css の font-family 先頭に "Noto Serif JP" を足すだけ（任意。T10 に含めない→§10）。

**論点 8 スタイルの置き場**: 現行は `css/print.css` が `media="print"` で、`.sh-*` の寸法は画面側（game.css）にある前提（measure() が画面で高さを測るため。**前提**: 実装者が game.css の `.sh-*` を確認）。本書では推挙状の見た目を print.css に集約し、index.html の link を `media="all"` にする（print.css 内の `@media print {}` で #app を隠す。#sheet は画面では v1 どおり画面外に置く）。これで AC-18' の色検査が print.css 1 本で済み、画面計測と印刷の寸法が一致する。

**論点 9 軍師の一言（D-23）**: 主 K1〜K4 の「主文」＋従 K1〜K4 の「従文」の 2 文を連結し、「」で囲む。texts.js に `sheet.hitokoto = { main:[4], sub:[4] }` を持ち、`一言 = main[top] + sub[second]`。主と従が同じ軸（想定外）のときは main だけ。文面は §3-2 表。決定的・通信不要（D-23）。現行 `axes[].line`（1 文×4）は使わなくなるので削除する（S4 は line を参照していない。result.js L49 のみ）。

### 3-4. 一の陣: 標本数の下限（A-3-1 への追加。検証 §4 (a)）

- 変更前: 押している間 50ms ごとに標本を 1 個取り、全標本をまとめて `g1Metrics(samples, tol)` へ渡す。標本 1 個（inSamples 1／totalSamples 1）で p1=p2=s=100 になる（検証報告_v1 §4-1、log-22 107 行目）。
- 変更後: **線ごとに**標本を持ち、「有効な線」の標本だけを採点に使う。
  - 有効な線 ＝ その線を**完了**した（終点到達）、**または** 標本数 ≥ `g1.minSamples`（**20 個＝50ms×20＝1 秒分**。こども・おとな共通）。
  - 有効な線が 0 本なら `g1Metrics([], tol)` → `{inSamples:0,totalSamples:0}`（maxDev なし）→ logic が 0 点（既存 L59・test_pure 29 行目の挙動）。＝「未完走扱い」。
  - 有効な線が 1 本以上なら、それらの標本を連結して v1 どおり計算（時間切れでも同じ。A-3-1「その時点までの標本」）。
- 選択肢と理由: (a) 線ごとの下限＋完了線は常に有効〔採用〕／(b) 全体の標本数に下限／(c) 下限未満を線外標本で埋めて比率を下げる。(a) は委任の「線 1 本あたり」に合い、素早く正しくなぞって完了した線（折れ線の飛び越し上限 120px/標本のため 700px の線は最短 6 標本で完了し得る）を無効にしない。(c) は maxDev が小さいままで p2 が高止まりし、意図が伝わりにくい。20 個の根拠: 線長 700px を 1 秒でなぞるのは「触れただけ」と「なぞった」の境目として十分短く、普通の操作（2〜5 秒＝40〜100 標本）を切らない。**前提**: 値は試遊で調整し得る（§11-2）。
- 実装の形（pure.js に純関数、g1.js は呼ぶだけ）:
  ```
  g1Filter(byLine, minSamples)  // byLine = [{samples:[d…], done:bool}…] → 有効線の d を連結した配列
  g1.js: samplesByLine[cur].samples.push(pr.d)；線完了で .done=true；finish で
         m = P.g1Metrics(P.g1Filter(samplesByLine, cfg.minSamples), tol)
  raw に lines（完了本数）・ms に加え perLine:[標本数×3]・valid:[有効 0/1×3] を追加（数値配列 ≤20 要素。A-6-5 の値域内）
  gameConfig(mode).g1.minSamples = 20 を追加（?debug=1 と AC-21 で見える）
  ```
- `g1Metrics` の署名・挙動は変えない（AC-07 の既存ケースはそのまま通る）。

### 3-5. 二の陣: 部品のつかみ判定（A-3-2「操作」への追加。検証 §4 (b)）

- 変更前: 部品 div ごとに pointerdown を付け、三角形は CSS clip-path で左下の直角三角形だけが当たり判定になる。外接矩形の中心 (60,60)〔部品内座標〕は斜辺上にあり、中心や辺の外側では押しても始まらない（検証報告_v1 §4-2）。
- 変更後: **つかみ判定をゲーム側の幾何計算**にし、「図形の内側＋余白」でつかめる。
  - 判定: 点 (x,y) が部品の**図形を余白 `g2.grabMargin`（12 論理 px）だけ外側に広げた領域**の中にあればつかめる。矩形＝各辺 ±12px。三角形（直角二等辺、直角は左下。頂点 (0,0)・(0,h)・(w,h)〔部品内座標、w=h=120〕）＝凸多角形の各辺について「外向きの符号付き距離 ≤ 12」をすべて満たす。
  - 候補が複数（置き場で余白が重なる）: 図形の内側（距離 ≤ 0）にある部品を優先、それも複数なら描画順の後（手前）。固定済み（p.fixed）は除外。
  - 実装: pointerdown を部品ごとではなく**ステージの root 1 か所**に付け、`P.g2PickPart(parts, centers, x, y, margin)` が返す添字の部品でドラッグを始める（setPointerCapture も root）。clip-path はそのまま見た目に残してよい（当たり判定に使わない）。pointermove／up の流れ・`g2Judge`・retries の数え方は変えない。
  - 余白 12px の根拠: 吸着半径（おとな 20）より小さく、操作対象 64px の目安（A-4）に対して「縁を少し外しても拾う」幅。三角形の外接矩形の直角の対角（右上角）は斜辺から 120/√2 ≈ 85px 離れるので、余白 12 では**つかめない**（委任の AC 条件）。
  - pure.js:
  ```
  g2Hit(part, cx, cy, x, y, margin) → boolean   // part.shape "rect"|"tri"、(cx,cy) は部品の中心
  g2PickPart(parts, centers, x, y, margin) → 添字 or -1   // 優先規則は上記
  gameConfig(mode).g2.grabMargin = 12（両モード）
  ```
  **前提**: 三角形の頂点配置「直角が左下」は検証報告の記述による。実装者は g2.css の clip-path と `g2Parts` の shape 定義で向きを確認し、違えば頂点をそれに合わせる（判定規則は同じ）。
