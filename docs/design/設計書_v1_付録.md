**_dev\router.php（ローカル代替）**: `php -S` は .htaccess を読まないため、router で次を 403 にする: パスが `/data/` で始まる／ファイル名が `.` か `_` で始まる／`/_dev/`。環境変数 `SJ_DELAY_MS`（API 応答を遅らせる）と `SJ_DOWN=1`（api を 503 にする）で通信不良を模擬。admin はローカルでは REMOTE_ADDR=127.0.0.1 のときだけ通す（A-7）。

## A-3. ミニゲーム 4 本の詳細仕様

共通 IF（各 gN.js）: `SJGame[N].start(ctx) → Promise<{m, end, raw}>`。`ctx = {mode:"adult"|"child", n, stageEl, debug}`。`m` は scoreGame にそのまま渡す指標オブジェクト（PRJ-105 logic L43-47 の入力形）、`end` は "done"／"timeout"、`raw` はログ用の短い要約。採点は app.js が `ShindanLogic.scoreGame(N, mode, m, params)` を呼ぶ（ゲーム内で点を計算しない。D-1）。時間はすべて `performance.now()` で測る。開始は 3・2・1 の後。

### A-3-1. 一の陣「しあげ」（K1）— 墨線なぞり

- 盤面: 板（矩形 x=190〜1090, y=200〜640、木目は CSS の縞）。線は 1 本ずつ表示し、終えると次の線。始点に朱の丸（半径 20）、終点に墨の丸（半径 20）。墨線の太さ 4px、許容幅の帯を薄く表示（おとな 12px／こども 24px。**論理 px**＝帯の片側幅。墨線までの距離 ≤ 許容幅で「線上」）。
- 線の形（論理座標。曲線は 200 点の折れ線に標本化して距離計算に使う）:

| 線 | こども（直線のみ） | おとな |
|---|---|---|
| 1 | 直線 (290,420)→(990,420) | 直線 (290,420)→(990,420) |
| 2 | 直線 (290,560)→(990,280) | 2 次曲線 (290,500) 制御 (640,240) →(990,500) |
| 3 | 直線 (640,250)→(640,600)（縦） | 3 次曲線 (290,420) 制御 (520,240)・(760,600) →(990,420) |

- 操作: 始点の丸の中（半径 30 以内）で左ボタンを押して開始。押している間だけ 50ms ごとに標本を取る（setInterval で最新ポインタ位置を読む）。離したら一時停止、現在の進み位置（折れ線上で最も進んだ点）から 40px 以内で押せば再開。進み位置が線長の 90% 以上に達し、ポインタが終点から 24px 以内に入ったら、その線は完了。
- 時間: 3 本の合計で上限 60 秒（目安 45 秒を説明文に出す）。線ごとの制限はない。
- 観測: 標本ごとの距離 d（折れ線までの最短距離。上限 200 で打ち切り）、線ごとの所要 ms、完走フラグ。
- 指標（pure.js `g1Metrics(samples, tol)`）: `inSamples` = d ≤ tol の数、`totalSamples` = 全標本数、`maxDev` = d の最大。**totalSamples=0 のときは maxDev を渡さない**（logic が悪値で採点する。L59）。scoreGame へ `{inSamples, totalSamples, maxDev}`。
- 時間切れ: その時点までの標本で計算（PRJ-105 §3-3）。完走フラグは raw にだけ入れる。
- 説明（こども）「すみの せんを、マウスの ボタンを おしたまま なぞろう。はみださないように！ 3ぼん」／（おとな）「板の墨線を、左ボタンを押したまま始点から終点へなぞってください。線からはみ出さない精度を見ます。3 本・目安 45 秒」

### A-3-2. 二の陣「くみたて」（K2）— 部品を影に置く

- 盤面: 左に組立台（x=80〜680, y=150〜650）に完成形の影（灰色の塗り）。右に部品置き場（x=760〜1200）。部品は回転なし・正しい向きで、置き場に縦に並べ、順番は n で決まる固定の入替え（`order = 定義順を n mod 部品数 だけ回す`）。
- 部品（矩形は 幅×高さ、三角は直角二等辺。中心の目標座標は組立台内）:

| 部品 | こども（3 個） | おとな（5 個） | 目標中心 |
|---|---|---|---|
| 台板 | 300×40 | 300×40 | (380,560) |
| 立て板 | 40×260 | 40×260 | (250,410) |
| 補強（三角） | 120 | 120 | (310,480) |
| 前の爪 | – | 40×60 | (510,510) |
| 上の帽子 | – | 80×30 | (250,265) |

  （題材はブックエンド。爪と帽子は形が似ており、取り違えが置き直しになる）
- 操作: 部品をドラッグ（pointerdown→move→up）。離した点で判定:
  - 部品の中心が自分の目標中心から吸着半径以内（おとな 20px／こども 40px＝2 倍）→ 目標に吸着して固定。
  - それ以外で組立台の中に落とした → **置き直し +1**、部品は置き場の元の位置へ戻る（揺れる演出）。
  - 置き場や台の外に落とした → 数えずに元の位置へ戻す。
- 終了: 全部品が固定された時点で完了（completed=true, seconds＝開始からの秒、小数 1 桁）。上限 60 秒で時間切れ（completed=false）。
- 指標: `{retries, seconds, completed}`（未完成は logic が 60 秒で採点。L61-62）。raw に置いた順（部品名の列）。
- 説明（こども）「みぎの ぶひんを ひだりの かげに ドラッグして くみたてよう」／（おとな）「右の部品を左の影の正しい位置へドラッグ。違う場所に置くと戻ります。速さと置き直しの少なさを見ます。上限 60 秒」

### A-3-3. 三の陣「しわけ」（K3）— 荷札で振り分け

- 盤面: ベルト（y=240〜340、x=0〜1280）を荷が左→右へ流れる。荷は 90×90 の箱で、札に「色＋記号」。下に行き先のレーン（蔵）を並べる。

| 行き先 | キー | 札（色・記号） | おとな | こども |
|---|---|---|---|---|
| 一番蔵（左） | ← | 朱・● | あり | あり |
| 二番蔵（中） | ↓ | 藍・▲ | あり | **なし**（↓ は無視・中レーン非表示） |
| 三番蔵（右） | → | 松葉・■ | あり | あり |

  記号だけでも判別できる（モノクロ・色覚に配慮）。札は行き先の中から一様乱数（mulberry32、seed＝n）で決める。
- 速度と間隔: おとな 160px/秒・1.2 秒ごと／こども 96px/秒（0.6 倍）・2.0 秒ごと。最初の荷は開始と同時に x=−90 から。
- 操作: キー ← ↓ →、またはレーン（下の 3 つの大きな枠）のクリック。押すと「まだ処理していない荷のうち最も右（先頭）」を処理し、正しければ正答、違えば誤答（荷はそのレーンへ落ちる演出）。画面に未処理の荷が無いときの入力は無視（数えない）。
- 見逃し: 未処理のまま右端（x>1280）を出た荷。
- 時間: 40 秒固定。終了時にベルト上に残る未処理の荷は数えない。
- 指標: `{correct, wrong, missed}`（logic が正答率と処理数＝正答数を出す。L70-71）。raw に入力の種類（key/click）の件数。
- 説明（こども）「にもつの ふだを みて、← → キーで ただしい くらへ わけよう」／（おとな）「流れてくる荷の札（色と記号）を見て ← ↓ → キーで 3 つの蔵へ振り分け。正確さと処理数を見ます。40 秒」

### A-3-4. 四の陣「しくみ」（K4）— フォークリフトの命令

- 盤面: 升目（おとな 5×5／こども 4×4、1 マス 90px、左上を (0,0)、x 右・y 下）。右側に命令欄（最大 8 枠）と命令ボタン ↑↓←→・「一つ消す」・「出陣」。
- 配置（固定。n が奇数のときは左右反転して出す。反転しても最短手数は同じ）:

| | おとな 5×5 | こども 4×4 |
|---|---|---|
| フォークリフト | (0,4) | (0,3) |
| 荷 | (3,2) | (2,1) |
| 障害物（棚） | (1,3)・(2,3)・(3,4) の 3 個 | (1,2) の 1 個 |
| 最短手数（BFS） | 5（↑↑→→→） | 4 |

  おとなは「先に右へ」が行き止まりになる配置。最短手数は pure.js の BFS で求めた値を使い、定義値と一致することを AC で確認する。
- 操作: 矢印キーまたはボタンで命令を追加（9 個目は受け付けず枠が揺れる）。Backspace／「一つ消す」で末尾を削除。Enter・Space・「出陣」で実行（命令 0 個は無視）。実行は 1 手 300ms のアニメ。
- 判定: 各手で移動先が壁か棚なら停止して失敗「ぶつかった！」。途中で荷のマスに入ったらその時点で成功。命令を使い切って荷に着かなければ失敗「とどかない」。失敗後は命令列を残したまま編集に戻る（並べ直し）。
- 終了: 成功で完了。上限 60 秒で時間切れ（実行アニメ中に 60 秒を迎えたらそのアニメの結果を待たずに打ち切り、成功扱いにしない）。
- 指標: `{success, runs, shortest, used}`。runs＝「出陣」の回数（成功した回を含む）、used＝成功した回の命令列の長さ、shortest＝定義の最短手数。未成功は logic が両指標 0（L76-79）。raw に各回の命令列（例 "RRU","UURRR"）。
- 説明（こども）「やじるしを ならべて『しゅつじん』！ フォークリフトを にもつまで うごかそう」／（おとな）「↑↓←→ の命令を最大 8 個並べて『出陣』。棚にぶつからずに荷へ。少ない試行・少ない命令ほど良い。上限 60 秒」

## A-6. サーバー API（PHP 8.2。api/api.php）

### A-6-1. 共通
- `date_default_timezone_set('Asia/Tokyo')`。応答は `application/json; charset=utf-8`、`Cache-Control: no-store`。
- 入口: `api/api.php?a=state|visitor|finish`。state は GET、他は POST（`Content-Type: application/json`）。
- 検査（順に）: メソッド（違えば 405）→ Origin（POST で Origin ヘッダーがあり、`https?://` ＋ Host と一致しなければ 403）→ 本文 ≤ 16KB（超えたら 413）→ JSON（不正は 400）→ 項目の許可リストと値域（外れは 400 `{"ok":false,"error":"bad_request","detail":"項目名"}`）→ 回数制限（IP ごと 5 分 300 回。超えたら 429。値は _config.php。ローカル試験用に cli-server のときだけ環境変数 `SJ_RATE_MAX` で上書き可）。
- 排他: 日ごとのロックファイル `data/state-{day}.lock` を `fopen('c')`→`flock(LOCK_EX|LOCK_NB)` を 50ms 間隔で最大 2 秒試行。取れなければ 503 `{"ok":false,"error":"busy"}`。JSON は `state-{day}.json.tmp-<pid>` に書いて `rename`。新規ファイルは `chmod 0600`。
- 例外・書込み失敗は 500 `{"ok":false,"error":"server"}`（詳細は返さない。`data/php-error.log` に追記）。

### A-6-2. データファイル（data/）
| ファイル | 中身 |
|---|---|
| settings.json | `{"degrade":false,"phase":"trial","overrides":{},"updated_at":"…"}`（無ければこの既定値として扱う） |
| state-{day}.json | `{"day":22,"seq":12,"counts":{"program_id":回数},"visitors":{"<client_id>:<local_seq>":n},"keys":{"<finish key>":1}}` |
| log-{day}.jsonl | 1 来場者 1 行（A-6-5） |
| rate.json | 回数制限の窓（IP のハッシュ → [時刻…]）。IP は sha256＋固定 salt で保存し生の IP は残さない |
| bak\ | 管理画面のリセット時の退避（state-22-YYYYMMDDHHMMSS.json） |

counts と n は**来場日 day（22/23/24）ごと**に別ファイル（＝日付リセット）。サーバーの日付ではなく day で分けるのは、10/20 試遊でも来場日を選んで遊ぶため。試遊で増えた分は 10/21 に管理画面でリセットする（配置手順に記載）。

### A-6-3. GET state
`api.php?a=state&day=22` → `{"ok":true,"serverTime":"2026-10-22T10:01:02+09:00","day":22,"seq":12,"counts":{…},"settings":{"degrade":false,"phase":"live","overrides":{…}}}`

### A-6-4. POST visitor（来場者番号の払い出し。D-13）
本文 `{"client_id":"c-1a2b3c4d","local_seq":17,"day":22}` → `{"ok":true,"n":13}`。ロック下で `visitors["c-1a2b3c4d:17"]` があればその n を返す（再送しても同じ番号＝冪等）。無ければ `seq+1` を払い出して記録。
client_id: `^c-[0-9a-f]{8}$`、local_seq: 1〜999999。

### A-6-5. POST finish（回数加算＋ログ追記。D-6・D-13）
本文（許可リスト。これ以外の項目は 400）:
```
{ "key":"c-1a2b3c4d-17", "client_id":"c-1a2b3c4d", "client_ts":"…", "v":"1.0.0",
  "day":22, "n":13, "n_source":"server"|"local", "ageClass":1, "mode":"child", "degrade":false,
  "games":[{"g":1,"end":"done","m":{…},"p1":..,"p2":..,"s":..,"raw":{…}}, …],  // 3 件（縮退）か 4 件
  "s":[..,..,..,..], "q1":"木", "q2":0, "q3":null,
  "top":0, "second":2, "picks":["futaba-T2",…], "honmei":"futaba-T2", "expCount":2,
  "counts_used":{…}, "ov":{…} }
```
- 値域: day 22/23/24、ageClass 0〜3、mode adult/child、s・p1・p2 は 0〜100、q1 は 5 値、q2 は -1/0/1、q3 は null か 3 値、picks は 0〜5 件で各 `^[a-z0-9]+(-[a-z0-9]+)*-[TVO][0-9]{1,2}$`、m・raw の値は数値・真偽・短い文字列（≤32 字）・それらの配列（≤20 要素）だけ。
- 処理（ロック下）: `keys[key]` があれば何もせず `{"ok":true,"dup":true,"counts":{…}}`。無ければ picks の各 id の counts を +1、`keys[key]=1`、state を保存し、`log-{day}.jsonl` に `{"ts":サーバー時刻,"phase":settings.phase, …本文}` を 1 行追記（`fopen('a')`＋改行）。`{"ok":true,"dup":false,"counts":{…}}`。
- 個人情報は無い（氏名・連絡先・顔・自由記述を受け取らない。IP はログに書かない）。

### A-6-6. クライアント（js/net.js）
- すべての fetch に `AbortController` で **2.5 秒**のタイムアウト。失敗しても画面は止めない。
- client_id: 初回に乱数 8 桁 16 進を作り localStorage `sj_client` に `{id, localSeq}` として保存（localStorage が使えなければメモリ上だけで続行）。
- 来場者番号: S1 確定時に localSeq+1 して visitor を呼ぶ。失敗時は `n = 1000000 + localSeq`、`n_source="local"`、表示は「第 L{localSeq} 号」。
- 設定と counts: S1 確定時に state を取得し、localStorage `sj_state_{day}` にキャッシュ。失敗時はキャッシュ（無ければ settings 既定値・counts {}）。**来場者 1 人の途中で設定は変えない**（S1 時点のものを使う）。
- recommend に渡す counts ＝ 直近の counts ＋ 送信キュー内の同じ day の未確認 finish の picks を +1 したもの。
- 送信キュー（localStorage `sj_queue`、最大 200 件、古いものから捨てる）: finish は**まずキューに積んでから**送る。`ok:true`（dup 含む）で削除し、返った counts でキャッシュを更新。ネットワーク失敗・429・503・500 は残して再送、400・403・413 は `sj_dead`（最大 50 件）へ移して再送しない。
- 再送の契機: 次の画面遷移ごと・`online` イベント・30 秒ごとのタイマー・`visibilitychange`（hidden）時は `fetch(…, {keepalive:true})`。同時に 1 件ずつ、古い順。重複はサーバーの key で防ぐ。
