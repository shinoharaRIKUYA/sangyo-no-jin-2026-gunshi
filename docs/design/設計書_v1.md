## 1. 目的と成功基準

**目的（言い換え）**: PRJ-105 の診断計算（shindan_logic.js）を一切変えずに呼び出す PC ブラウザゲーム「AI軍師の仕官相談所」を作る。入口→ミニゲーム 4 本→軍師の問い→見立て→推挙状 A4 印刷までを 2 台以上で遊べ、推挙回数とログはサーバー（PHP）で共有し、通信が切れても止まらないようにする。

**成功基準（確定案。G2 で台帳 §1 に転記）**:

1. 入口から推挙状印刷まで、こども／おとな両モードで通しで遊べる（目安 約 6 分、縮退 約 5 分）。放置すると受付画面に戻る（AC-04・AC-05・AC-19）。
2. 推挙結果（5 件の順・本命）が、同じ入力で shindan_logic.js を直接呼んだ結果と全件一致する。ゲームは計算を再実装せず、PRJ-105 の 3 ファイルは無変更コピー（AC-01・AC-02・AC-06）。
3. 来場者番号はサーバー連番、推挙回数はサーバー加算で、2 台同時でも数がずれない。通信断でも最後まで遊べ、復帰後に後送され二重計上しない。ログに個人情報を持たない（AC-08〜AC-12・AC-22）。
4. 管理画面（Basic 認証）から、縮退（3 本＋Q3）・要確認行の推挙可否・回数リセット・ログ CSV 書出しを操作でき、次の来場者から反映される（AC-13〜AC-16）。
5. 推挙状は A4 縦 1 枚・モノクロで読め、既定プリンターへの印刷（--kiosk-printing）とダイアログ印刷のどちらでも出せる（AC-17・AC-18）。
6. 公開先 https://coco529.sakura.ne.jp/dev/sj2026-gunshi/ で動作確認できる。データ・管理の保護が効いている（AC-26。公開は G3 の名指し承認後に P6 で実施）。

## 3. 方式

### 3-1. 全体の構成（A-1）
- 選択肢: (a) 静的 HTML/JS（1 ページ）＋薄い PHP API ／ (b) PHP でサーバー描画 ／ (c) フレームワーク（React 等）。
- **採用: (a)。** logic は DOM に触れない通常 script で、読込順 params→data→logic のグローバル前提（R1 §2・§8）。ビルド不要の素の JS が最も合う。API は 3 本（state・visitor・finish）で足りる（R2 §7「2 本程度の薄い PHP」に、n 払い出しを加えた）。
- 退けた案: (b) 画面遷移とゲームのたびに往復が生じ、通信断で止まる（D-6）。(c) ビルド工程が増え、var グローバル前提と相性が悪い（logic L6-10）。
- 公開単位は `output\sj2026-gunshi\`（フォルダ名は §11-1）。参照は相対パスのみ（R2 §2・§7）。

### 3-2. 計算の呼び方（D-1）
- PRJ-105 の shindan_params.js・shindan_data.js・shindan_logic.js を無変更でコピーし、通常の `<script>` で params→data→logic の順に読む（logic L6-10）。
- 各陣はゲーム内で点を出さず、logic の入力形の**指標**だけを返す（一の陣 `{inSamples,totalSamples,maxDev}`／二の陣 `{retries,seconds,completed}`／三の陣 `{correct,wrong,missed}`／四の陣 `{success,runs,shortest,used}`。logic L43-47、R1 §2）。採点は `scoreGame`、推挙は `recommend`、モードは `modeOf` を呼ぶだけ（A-3-6）。
- 指標の計算（許容幅判定・見逃し・最短手数）はゲーム側の責任（R1 §8 落とし穴）なので、`js/pure.js` の純関数にまとめ node で単体テストする（AC-07）。
- 縮退・上書きは「params・data の複製を変える」方式: 有効パラメータは params の複製で `axisSource.K4` だけ切替、データは行の浅い複製に上書きを適用（A-7-2）。ファイルは変えない（R1 §5「params を複製して上書きしても動く」）。
- 縮退時 s[3]＝0、q3 必須（logic L176-182、R1 §5）。recommend の結果は 1 回だけ計算して印刷まで保持（R1 §8）。

### 3-3. ミニゲームの具体形（A-3）
- 論点 1 盤面サイズ: (a) 画面 px のまま ／ (b) 1280×720 の論理ステージを拡縮。**採用 (b)**。許容幅 12/24px が解像度で意味を変える問題（R1 §1 未確認）を避け、1920×1080 と 1366×768 で同じ難度にする。
- 論点 2 一の陣の時間: 3 本合計で上限 60 秒、目安 45 秒を説明に表示。時間切れはその時点の標本で採点（PRJ-105 §3-3「その時点のログで計算」、R1 §1 推定）。おとなは直線 1・曲線 2、こどもは直線 3（PRJ-105 §3-3「こどもは直線のみ」）。
- 論点 3 時間切れの見せ方（台帳 §5-2）: 残り時間の帯（残り 10 秒で朱）＋終了時「そこまで！」1.5 秒。点数は見せない（PRJ-105 §3-3 表示ルール）。
- 論点 4 四の陣: 固定配置（n 奇数で左右反転）・最短手数は BFS で検証。毎回乱数配置は最短手数の保証と難度の揃いが難しいため退けた。
- 三の陣のこどもは ↓ を無視し中レーンを出さない（R1 §1 推定）。札は色＋記号の二重表示（モノクロ・色覚配慮）。
- 各値（寸法・速度・吸着半径・配置）は A-3 に確定値。閾値は PRJ-105 params のまま（表 3-3-a）。

### 3-4. 画面・文言・放置（A-2）
- 画面は S0 受付→S1 入口→説明＋陣×4（縮退 3）→問い 2（縮退 3）→S4 見立て→S5 印刷→S0。こども／おとなで文言を分け texts.js に集約（A-2 表・A-3 各説明）。
- 放置: 入口・説明・問い・見立てで無操作 60 秒→「つづけますか？」10 秒→受付へ。印刷後 30 秒で受付へ（A-2-2）。ゲーム中は制限時間で自然に終わるので対象外。
- 係用の隠し操作（Ctrl+Alt+K の係パネル）と `?debug=1` を設け、本番の来場者画面には数値を出さない（R1 §8 落とし穴）。

### 3-5. 推挙状（A-5。D-2・D-10・D-12）
- 用紙: **A4 縦**（D-10）。`@page { size: A4 portrait; margin: 12mm }`（R2 §4 事実）。色は黒・灰のみ、背景なし。
- 内容: 表題・仕官番号・来場日・見立て（主・従の傾向語）・推挙 5 件のカード（区分・出展者名・プログラム名・開催日・予約・所要・費用・年齢・カード注記）・本命は「◎ 本命」と太枠・体験 0 件の文言・定型文（場所・時刻・電話は受付／公式サイトで確認。D-12）。
- 表示の言い換え（予約区分・年齢注記の表記ゆれ）は表示関数で行い、データは変えない（A-5 表。R1 §3・§7-4）。
- 1 枚に収める: 印刷前に高さを測り超えたら縮小（A-5）。
- 印刷: `window.print()` 1 回。会場は `--kiosk --kiosk-printing` で既定プリンターへ直接、ダイアログ環境でも同じ操作で成立（D-10、R2 §4）。プリンター名には依存しない（D-15）。

### 3-6. サーバー共有（A-6。D-6・D-9・D-13）
- 論点 1 置き場: 公開フォルダ内 `data/`（D-9）。.htaccess の全拒否＋ファイル 0600・ディレクトリ 700 の二重化（R2 §5 推定・§7）。
- 論点 2 n と counts: n は日ごとのサーバー連番、counts はサーバーで +1（D-13、R1 §4 推定の lost update 回避）。来場日 day ごとのファイルで「日付リセット」を兼ねる。
- 論点 3 排他: 日ごとのロックファイル＋LOCK_NB で最大 2 秒試行＋一時ファイル→rename、ログは同じロック下で追記（R2 §3 事実・推定。/home は local ufs）。
- 論点 4 冪等: visitor は (client_id, local_seq)、finish は key で重複を吸収（R2 §4 推定「冪等キー＝端末 ID＋連番」）。
- 論点 5 通信断: fetch 2.5 秒タイムアウト、finish は先に localStorage のキューへ積んでから送信、契機ごとに再送、離脱時は keepalive。オフライン時の n は `1000000+localSeq`（logic は有限数なら可。L175）、counts は直近値＋未送信分（A-6-6）。
- 論点 6 入力検証: 許可リスト・値域・16KB 上限・Origin・IP ごとの回数制限（R2 §5 推定）。完全な改ざん防止は不可（R2 §5）だが、受け付けるのは数値と決まった文字列だけ。
- 退けた案: 公開領域外（R2 推奨）は D-9 でユーザーが公開フォルダ内を指定したため採らない。取得→書戻し方式は 2 台で上書きが起きる（R1 §4 推定）。SQLite は php -m で未確認（R2 §3）。

### 3-7. 管理画面（A-7。D-11）
- Basic 認証（.htpasswd は公開領域外、P6 でユーザー本人が作成）＋ PHP 側で認証変数が無ければ拒否（二重化）。ローカルでは 127.0.0.1 のみ。
- 機能: 縮退切替／要確認行の「推挙する」（年齢下限区分・予約区分の入力必須）と通常行の「推挙しない」／試遊・本番の区分／日ごとの counts 表示とリセット（退避あり）／ログ CSV 書出し。設定は settings.json、ゲームは次の来場者の入口で読み込む。
- 「推挙しない」を加えたのは、当日に体験が埋まった枠を外す受け皿（PRJ-105 R-5）。

### 3-8. 見た目（A-4。D-4）
- 和紙色の地・墨の線・朱と藍の差し色、明朝の見出し＋ゴシックの本文、画像・Web フォント・CDN なし（通信断でも崩れない）。
