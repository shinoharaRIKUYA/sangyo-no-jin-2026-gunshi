## 2. data の権限（統合役）

```
chmod 700 ~/www/dev/sj2026-gunshi/data
```

- PHP（さくらの CGI 実行。所有者権限）が作るファイルは `chmod 0600` になる（_lib.php）。.htaccess が効かない場合でも Web サーバーから直接配信されない（二重化）。

## 3. 管理画面の Basic 認証（ユーザー本人。D-17）

```
ssh coco529
mkdir -m 700 ~/sj2026-gunshi-auth
htpasswd -c -B ~/sj2026-gunshi-auth/.htpasswd <ユーザー名>
chmod 644 ~/sj2026-gunshi-auth/.htpasswd
```

- パスワードは対話入力。どこにも書かない。サーバーに `htpasswd` が無い場合は、本人の PC で `C:\xampp\apache\bin\htpasswd.exe -c -B <保存先>\.htpasswd <ユーザー名>` で作り、本人が `scp` で `~/sj2026-gunshi-auth/` に置く。
- `admin\.htaccess` の `AuthUserFile` は `/home/coco529/sj2026-gunshi-auth/.htpasswd`（作成済み・変更不要）。
- **§4 の確認で `/admin/` が 401 ではなく 500 になる場合**（レビュー指摘 #2・D-21）: Apache が別ユーザー権限で `.htpasswd` を読めていない可能性が高い。ディレクトリを 705、ファイルを 604 に変えて再確認する。公開領域（`~/www/`）の外なので URL からは読めない。

```
chmod 705 ~/sj2026-gunshi-auth
chmod 604 ~/sj2026-gunshi-auth/.htpasswd
```

  それでも 500 なら、さくらのコントロールパネルのエラーログで `AuthUserFile` 行を確認する（パスワードはどこにも書かない）。
